# Дашборд сезонности цен (Aviasales / Travelpayouts API)

## Историческая статистика регулярного рейса

`FlightHistoryAggregator.aggregate(List<FlightRecord>)` возвращает карту
`flightServiceKey -> FlightHistoricalStats`, где ключ — `airlineIata|flightNumber|originIata|destinationIata`.
`aggregateFor(flights, "DP", "6525", "SVO", "OVB")` возвращает `Optional` для одного рейса.

Перед группировкой выбирается одна запись на `flightId`: самая поздняя по `collectedAtUtc`,
затем наиболее полная (задержки и scheduled departure local), затем наблюдение вылета,
затем порядок `FlightRecord.toString()` — та же стратегия, что у `DelayAnalyzer`.
Поля разных наблюдений не объединяются. Строки без ID или полного ключа исключаются.
Компоненты ключа используются как есть; пустые компоненты и компоненты с `|` не допускаются.

`sampleSize` включает отмены и записи без задержек. Каждая метрика задержки использует
свои ненулевые значения неотменённых рейсов, без дополнительного фильтра по статусу.
При отсутствии значений медиана, среднее и вероятности равны `null`.
Пороги вероятностей строгие (`> 15/30/60`); доля отмен делится на `sampleSize`.
Компенсация — задержка вылета минус задержка прилёта, только при наличии обеих в одной записи.
Ограничение по датам задаётся входным списком, сам агрегатор даты не фильтрует.

Standalone smoke-test без дополнительных зависимостей (JDK 17+, из корня проекта):

```powershell
javac -encoding UTF-8 --release 17 -d target/history-test -sourcepath "src/main/java;src/test/java" src/test/java/avia/FlightHistoryAggregatorTest.java
java -cp target/history-test avia.FlightHistoryAggregatorTest
# Необязательно: прочитать локальные CSV за 2026-09-27 — 2026-10-03 и вывести DP 6525.
java -cp target/history-test avia.FlightHistoryAggregatorTest data/flights
```

Тест запускается отдельно от `mvn test`, сетевых запросов не делает.

## Модуль задержек рейсов (ветка task3)

Добавлен pipeline AeroDataBox FIDS → нормализация → отдельные CSV batches.
JSON-контракт сверяется с [официальной спецификацией RapidAPI](https://doc.aerodatabox.com/docs/openapi-rapidapi-v1.json).

Импорт сохранённого ответа с `withLeg=true` (ключ не нужен):

```powershell
java -jar target/avia-seasonality.jar --delays-import response.json SVO 2026-10-03 00 12
```

Реальный запрос через RapidAPI — ключ задаётся в **той же PowerShell-сессии**, где запускается Java:

```powershell
$env:AERODATABOX_API_KEY = "YOUR_RAPIDAPI_KEY"
java -jar target/avia-seasonality.jar --delays-health UUEE
java -jar target/avia-seasonality.jar --delays-airport SVO
java -jar target/avia-seasonality.jar --delays SVO 2026-10-03 00 12
```

Если ключ уже сохранён в пользовательских переменных Windows, перед запуском в новой
PowerShell-сессии его можно загрузить без повторного ввода:

```powershell
$env:AERODATABOX_API_KEY = [Environment]::GetEnvironmentVariable('AERODATABOX_API_KEY', 'User')
```

`--delays-airport` получает справочные данные через `/airports/{codeType}/{code}` и сохраняет
их в `data/reference/airports/SVO.json`. Повторный вызов использует готовый файл без запроса.
Для получения обновлённого справочника нужно явно убрать/переместить старый кэш.
Сбор и импорт автоматически используют уже сохранённый справочник наблюдаемого аэропорта;
если его нет, дополнительные API-запросы не выполняются, недостающие поля остаются пустыми.

Для применения справочника к уже собранным данным:

```powershell
java -jar target/avia-seasonality.jar --delays-reprocess SVO 2026-10-03 00 12
```

Команда пересоздаёт CSV из `data/raw/` **без сети и ключа**, сохраняя исходный JSON и его
время сбора. Без часов обрабатывает оба окна дня. Если JSON отсутствует, завершится ошибкой,
а не новым запросом. Для обычного `--delays` существующий CSV по-прежнему пропускается.

Для целого дня: `--delays SVO 2026-10-03` (два запроса: 00–12 и 12–24).
Доступность даты и стоимость определяет подписка API. Проверяйте coverage до массового сбора.
Без доступного ключа приложение завершается до сетевого запроса.

Выходные файлы: `data/flights/2026-10-03/SVO_00-12.csv` и, при сетевом сборе,
`data/raw/2026-10-03/SVO_00-12.json`. Готовый CSV пропускается; если CSV ещё нет,
сохранённый JSON используется повторно без API-запроса. Автоматических сетевых повторов нет.
Файлы `data/` исключены из Git. Повторный запуск не обновляет существующий snapshot:
для свежей выборки нужен отдельный batch/явное управление сохранёнными файлами.

Окна задаются целыми часами, длительность 1–12 часов, `24` означает полночь следующего дня.
Окно запроса не является фильтром scheduled time. Поля отсутствующего второго leg остаются пустыми.
UTC используется для задержек, scheduled local time — для часа и дня недели.
Отрицательные задержки сохраняются. Отменённые рейсы сохраняются, их метрики задержки пусты.
Если для стабильного `flight_id` недостаточно полей, ID остаётся пустым: такие записи нельзя
безопасно дедуплицировать по ID. Само устранение дублей между batches пока не реализовано.
`collected_at_utc` при импорте берётся из времени изменения JSON-файла; при копировании
файла это может отличаться от фактического момента исходного запроса.

Локальная проверка на синтетическом JSON: запустите `avia.FlightPipelineTest` из `src/test/java`
с рабочим каталогом корня проекта. Тест не обращается к AeroDataBox; HTTP проверяется
локальным mock-сервером. Это отдельный исполняемый smoke-test, не JUnit-тест для `mvn test`.
`avia.DelayAnalysisTest` проверяет CSV round-trip, дедупликацию, медиану, знаменатели долей,
пропуски, малые группы и генерацию HTML. Оба исполняемых теста запускаются отдельно от `mvn test`.
Первый реальный пилот: [SVO за 2026-10-03](docs/SVO_PILOT_2026-10-03.md).

### Пять аэропортов, пакетный сбор и теплокарта

По умолчанию в выборку входят **SVO, LED, AER, OVB, SVX** из плана реализации.

```powershell
# Предварительный план: без ключа, без сети и без расхода units.
java -jar target/avia-seasonality.jar --delays-plan 2026-09-27 2026-10-03

# Сбор: явный верхний предел НОВЫХ FIDS-запросов, здесь 60.
java -jar target/avia-seasonality.jar --delays-collect 2026-09-27 2026-10-03 60

# Отчёт: медиана задержки по локальному дню недели и часу вылета, N >= 30.
java -jar target/avia-seasonality.jar --delays-report 2026-10-03 2026-10-03 30

# Предварительный просмотр малых групп, не для статистических выводов.
java -jar target/avia-seasonality.jar --delays-report 2026-10-03 2026-10-03 1
```

Последний необязательный аргумент — список аэропортов через запятую. Для `--delays-report`
перед списком обязательно указывается минимальный размер группы.

Сбор пропускает существующие CSV и повторно использует JSON. До сетевого сбора проверяется
`liveFlightUpdatesFeed` каждого аэропорта с новыми FIDS-запросами: требуется `OK`.
Отсутствующие справочники загружаются один раз. **Лимит ограничивает число FIDS-запросов,
а не API units и не общее число HTTP-запросов:** запросы coverage и справочников идут дополнительно.
Фактическую квоту и тарификацию нужно проверять в подписке; код не узнаёт баланс аккаунта.
При превышении заданного лимита сбор не начинается; при ошибке, включая HTTP 429, останавливается
без автоматического повтора. Журнал — `data/collection.jsonl`. Повторный запуск продолжит
с недостающих batches. Не запускайте несколько сборщиков одновременно.

Отчёт сохраняется в `reports/delays_FROM_TO_nN.html`, работает локально без внешних библиотек,
содержит пять теплокарт с общей шкалой, переключатель аэропорта и таблицы по аэропорту вылета,
авиакомпании и маршруту. Показывает число загруженных batches и исключённых наблюдений.

Аналитика читает CSV через `FlightReader`. Для совпавших ID выбирается самая поздняя строка
по `collected_at_utc`; при равенстве — более полная, затем наблюдение вылета, затем детерминированный
порядок полей. Строки не сливаются по отдельным полям, поэтому более новая строка может иметь
больше пропусков. Строки без ID исключены из агрегатов и посчитаны отдельно.
Далее применяется фильтр по аэропорту **вылета** и scheduled departure local в выбранном периоде.
Чтение охватывает только запрошенные даты batches: рейсы, попавшие исключительно в соседние
окна за пределами этих дат, могут отсутствовать в отчёте.

Для задержек вылета принимаются `Departed`/`Arrived`, для прилёта и компенсации — `Arrived`.
Отмены не участвуют в задержках. `P(delay > 15/30/60)` делится на число доступных задержек
вылета; доля отмен — на число рейсов группы. Каждая метрика имеет свой размер выборки.
При N ниже порога медиана/доля не отображается. `revisedTime` может быть оценочным даже
при выбранных статусах; отчёт не заменяет проверку качества операционных данных.

Срез пяти аэропортов за один день: [описание датасета](docs/FIVE_AIRPORT_PILOT_2026-10-03.md).
Недельный срез **2026-09-27 — 2026-10-03**: [состав, проверки и ограничения](docs/FIVE_AIRPORT_WEEK_2026-09-27_2026-10-03.md).
Собраны все 70 batches, 12 666 исходных записей; отчёты находятся в `reports/`.

Небольшой Java-проект: строит тепловую карту «месяц × день недели вылета»,
чтобы понять, когда дешевле лететь по выбранному направлению.

## Сборка

```bash
mvn clean package
```

Соберётся `target/avia-seasonality.jar` (используется maven-shade-plugin,
все зависимости уже внутри jar).

## Запуск

```bash
java -jar target/avia-seasonality.jar MOW BKK ВАШ_ТОКЕН rub
java -jar target/avia-seasonality.jar MOW ВАШ_ТОКЕН rub
java -jar target/avia-seasonality.jar --transfers MOW ВАШ_ТОКЕН rub
```

Параметры:
- `ORIGIN` — IATA-код города вылета (например, `MOW` — Москва)
- `DESTINATION` — IATA-код города назначения (например, `BKK` — Бангкок), опционален
- `TOKEN` — партнёрский API-ключ
- `CURRENCY` — необязательно, по умолчанию `rub`

## Результат
Режим с `DESTINATION`:
- `heatmap_ORIGIN_DESTINATION.html` — тепловая карта "когда дешевле лететь" по выбранному направлению
- `raw_prices_ORIGIN_DESTINATION.csv` — сырые данные

Режим без `DESTINATION`:
- `heatmap_ORIGIN_any_destination.html` — тепловая карта "куда дешевле лететь" (в ячейке направление + средняя цена)
- `raw_prices_ORIGIN_any.csv` — сырые данные по разным направлениям

Режим `--transfers` (сравнение прямых и пересадочных рейсов по направлениям):
- `transfers_comparison_ORIGIN.html` — диаграмма и таблица: цена прямого рейса
  vs 1 и 2 пересадок по каждому направлению из ORIGIN, отсортировано по выгоде
  от пересадки
- `transfers_comparison_ORIGIN.csv` — та же агрегированная таблица для pandas/Excel
- `raw_transfers_ORIGIN.csv` — сырые предложения (направление, число пересадок, цена)

## Как это устроено
Режимы сезонности используют метод `/v1/prices/calendar` с пустым `departure_date` —
в этом случае Aviasales отдаёт одну (самую дешёвую) цену на **каждый день
ближайшего года** одним запросом. Дальше в Java-коде это просто
группируется по месяцу и дню недели и усредняется.

Режим `--transfers` использует метод `/v1/prices/cheap` с `destination=-`:
одним запросом он отдаёт по каждому направлению из ORIGIN до трёх предложений,
сгруппированных по числу пересадок (0/1/2). Java-код раскладывает их по
направлениям и считает разницу между ценой прямого рейса и самой дешёвой
пересадочной альтернативой — в рублях и в процентах.

## Ограничения источника данных
- Данные берутся из кэша поисков пользователей Aviasales (актуальность —
  до 7 дней), а не из "истории цен за прошлый год" в чистом виде — то есть
  это скорее срез "что ищут сейчас на ближайший год", а не ретроспектива.
- На какие-то даты в кэше может не быть данных — такие ячейки в тепловой
  карте помечены прочерком.
- У метода `/v1/prices/calendar` лимит 10 запросов в секунду — в этом
  проекте используется один запрос на весь год, так что лимит не проблема.
